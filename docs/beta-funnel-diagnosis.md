# Diagnostico do funil beta

Data: 2026-06-12

## Funil esperado

1. Visitante entende que o produto gera respostas para WhatsApp manual.
2. Usuario cria conta.
3. Usuario conclui onboarding.
4. Usuario cola uma mensagem real de cliente.
5. Usuario gera a primeira resposta.
6. Usuario copia, ajusta ou salva a resposta.
7. Usuario envia feedback ou abre suporte se houver problema.
8. Usuario entende o limite e escolhe plano quando fizer sentido.

## Evidencia disponivel

Os relatorios atuais documentam fluxo, checklist e smoke local, mas nao trazem volume real por etapa. Portanto, nao e possivel afirmar taxa de conversao, retencao, satisfacao ou churn de beta.

## Diagnostico por etapa

- Landing: precisa manter o aviso de que nao ha envio automatico pelo WhatsApp.
- Cadastro/login: sem evidencias de falha real, mas precisa ser validado no ambiente final.
- Onboarding: labels foram ajustados para explicar melhor negocio, tipo de atendimento, tom e oferta.
- Primeira resposta: CTA foi simplificado para "Gerar resposta" e a instrucao inicial ficou mais direta.
- Qualidade da IA: prompt reforcado para nao inventar preco, prazo, estoque, agenda ou disponibilidade.
- Templates: catalogo cobre preco, entrega, agendamento, disponibilidade, pagamento, orcamento, horario e pos-venda.
- Suporte/feedback: fluxo existe, mas precisa receber dados reais de usuarios beta.

## Metricas a preencher na proxima rodada

- Visitantes da landing.
- Cadastros iniciados e concluidos.
- Onboarding concluido.
- Primeira resposta gerada.
- Resposta copiada.
- Resposta salva.
- Feedback positivo/negativo.
- Tickets de suporte por categoria.
- Erros de geracao.
- Conversao para plano pago.
